## Requirements
### Requirement: 完全重複排除を伴う履歴追加
`InputHistory.Add` は空白のみ（`IsNullOrWhiteSpace`）のテキストを無視し、既存エントリの中に完全一致するテキストがあれば連続・非連続を問わず全て取り除いた上で新規エントリを末尾に追加しなければならない (SHALL)。共通入力欄からの送信（通常送信・全ペインブロードキャスト送信・番号指定送信のいずれの経路でも）は、選択範囲がある場合はその選択テキストのみを、無い場合は入力欄全文を `Add` に渡す。

#### Scenario: 空白のみの入力は無視される
- **WHEN** 空文字列・スペースのみ・タブや改行のみのテキストで `Add` を呼ぶ
- **THEN** 履歴には追加されず `Count` は変化しない

#### Scenario: 非連続の重複は古い方が除去される
- **WHEN** "a" → "b" → "a" の順で `Add` を呼ぶ
- **THEN** 最初の "a" は履歴から取り除かれ、履歴は末尾から見て "a", "b" の順（"a" が最新）になる

#### Scenario: いずれの送信経路も履歴に追加される
- **WHEN** ユーザーが通常送信・Ctrl+Shift+S の全ペインブロードキャスト送信・Ctrl+1..9 の番号指定送信のいずれかでコマンドを送信する
- **THEN** amm は送信直後に `_inputHistory.Add(rawText)` を呼び、続けて `_inputHistory.ResetCursor()` でカーソルを末尾へ戻す

### Requirement: 上限件数の管理と切り詰め
`InputHistory` はコンストラクタ引数（既定 `DefaultMaxEntries`=500）で保持件数の上限を持ち、`Add` により件数が上限を超えた場合は先頭（最古）のエントリから 1 件破棄しなければならない (SHALL)。`SetMaxEntries` で上限を実行時に変更でき、新しい上限は 1 未満にはクランプされず最小 1 に丸められ、新上限が現件数より小さい場合は古い順から切り詰め、カーソルが範囲外になれば件数に合わせて補正する。

#### Scenario: 追加時に上限を超えたら最古を破棄
- **WHEN** 上限3件の `InputHistory` に "a","b","c","d" の順で `Add` する
- **THEN** 最古の "a" が破棄され、履歴には "b","c","d" が残る

#### Scenario: SetMaxEntries で上限を縮小すると古い順に切り捨てられる
- **WHEN** 上限10件で "a","b","c","d" を追加した後に `SetMaxEntries(2)` を呼ぶ
- **THEN** `Count` は2になり、残るのは最新2件の "c","d" である

#### Scenario: 上限に0や負数を渡すと1にクランプされる
- **WHEN** `SetMaxEntries(0)` または負数を渡す
- **THEN** `MaxEntries` は1になり、既存エントリは最新1件のみが残る

### Requirement: カーソルベースの前後移動 API
`InputHistory` は内部カーソルを持ち、`NavigateUp` は現在位置から過去方向へ、`NavigateDown` は未来方向へ1件ずつ移動して該当エントリを返さなければならない (SHALL)。エントリが0件の場合は両メソッドとも null を返す。`NavigateUp` は先頭（最古）に達すると同じ値を返し続け（それ以上戻らない）、`NavigateDown` は末尾を超えると空文字列を返しカーソルを末尾（件数と同じ位置＝「未選択」状態）にリセットする。`ResetCursor` はカーソルを明示的に末尾へ戻す。ただし 2026-07-10 時点のソースを確認する限り `MdiParentForm` はこれら2メソッドを一切呼び出しておらず、`OnInputBoxKeyDown` には「↑/↓ で履歴ナビゲーションする旧仕様は廃止（誤操作の温床）」という趣旨のコメントが残っている。現行 UI にはこの2メソッドを呼ぶ経路が無く、ユニットテストのみがその契約を検証している。

#### Scenario: 空履歴でのナビゲーション
- **WHEN** エントリが1件も無い状態で `NavigateUp` または `NavigateDown` を呼ぶ
- **THEN** どちらも null を返す

#### Scenario: 上方向への連続移動と下限での停止
- **WHEN** "a","b","c" を追加した直後に `NavigateUp` を4回連続で呼ぶ
- **THEN** 返り値は "c","b","a","a" の順になり、最古に達すると同じ値を返し続ける

#### Scenario: 下方向で末尾を超えるとクリアされる
- **WHEN** `NavigateUp` を2回呼んで過去方向へ移動した後、`NavigateDown` を末尾に達するまで呼び続ける
- **THEN** 末尾到達時点で空文字列 `""` を返し、カーソルは件数と同じ位置（末尾）にリセットされる

### Requirement: 一括ロード／スナップショットによる永続化
`InputHistory` は `LoadFromOldestFirst`（古→新順のリストから一括復元、空白エントリは除外、上限超過分は最古側から切り詰め、復元後カーソルは末尾）と `SnapshotOldestFirst`（古→新順の読み取り専用スナップショット）を提供しなければならない (SHALL)。amm はこれらを用いて上限件数・古→新順の全エントリをアプリ終了時に保存し、次回起動時に復元する。これにより入力履歴は（ペインごとの下書きテキストとは異なり）amm 再起動をまたいで保持される。永続化先は、実行ファイル自身の設置ディレクトリへの書き込み権限に依存しない、現在の OS ユーザーが常に書き込み可能な場所（例: Windows の `%LOCALAPPDATA%` 配下）でなければならない (SHALL)。標準的なインストーラ配置（`C:\Program Files\` 等、非管理者ユーザーが書き込めない場所）へインストールされた場合でも、この永続化は失敗してはならない (SHALL NOT)。永続化を単一のファイル（`layout.json` に同梱するか、専用ファイルとして分離するか）で行うか複数ファイルに分けるかは実装の裁量とする。

#### Scenario: 起動時復元
- **WHEN** amm 起動時に永続化先に上限件数と古→新順のエントリ一覧が保存されている
- **THEN** amm はまず上限件数を反映し、続けて `LoadFromOldestFirst` で復元する
- **AND** 復元直後に `NavigateUp` を呼ぶと最新のエントリが返る

#### Scenario: 終了時のスナップショット書き出し
- **WHEN** amm 終了時に履歴を永続化する
- **THEN** `SnapshotOldestFirst()` の結果が古→新順のまま永続化先に書き込まれ、次回起動時に同じ順序で復元される

#### Scenario: 空白エントリを含むデータからの復元
- **WHEN** `LoadFromOldestFirst` に空文字列やホワイトスペースのみの要素を含むリストを渡す
- **THEN** それらの要素は除外され、有効な非空エントリのみが履歴として復元される

#### Scenario: 非管理者権限での標準インストール配置でも永続化に失敗しない
- **WHEN** amm が `C:\Program Files\amm\` のような非管理者ユーザーが書き込めない場所にインストールされている
- **THEN** 入力履歴の永続化はユーザー単位の書き込み可能な場所（実行ファイルの設置場所に依存しない場所）を使用し、再起動後も履歴が保持される

### Requirement: 履歴ドロップダウンによる UI 提示
共有入力欄の履歴呼び出しは「履歴 ▼」ボタンのクリック、または Ctrl+H ショートカット（`OnInputBoxKeyDown` が同一ハンドラ `OnHistoryButtonClick` を呼ぶ）からのみ行わなければならない (SHALL)。呼び出されると amm は `GetRecent(20)` で直近20件を新しい順に取得し、各エントリの改行 (`\r\n`/`\n`/`\r`) を可視マーカーに置換し80文字を超える場合は末尾を省略した上でコンテキストメニューとして表示する。項目をクリックすると入力欄のテキストが選択したエントリで置き換わり、キャレットは末尾に移動する。

#### Scenario: 履歴が空の場合
- **WHEN** 履歴が0件の状態で「履歴 ▼」ボタンまたは Ctrl+H を操作する
- **THEN** amm は「(履歴なし)」という無効化された1項目のみのメニューを表示する

#### Scenario: 履歴項目の選択で入力欄に反映
- **WHEN** ドロップダウンに表示された履歴項目の1つをクリックする
- **THEN** amm は入力欄のテキストを選択したエントリの全文で置き換え、キャレットを末尾に移動してフォーカスを入力欄に戻す
- **AND** この操作は `InputHistory` の内部カーソルやエントリ内容そのものは変更しない（`GetRecent` は読み取り専用の一覧生成であり `NavigateUp`/`NavigateDown` を経由しない）
