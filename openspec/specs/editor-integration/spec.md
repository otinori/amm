# editor-integration Specification

## Purpose
amm の GUI 本体(Tauri版、`src/apps/Amm/`)における、ペイン単位のエディタ連携機能の仕様。入力欄の下書きを外部エディタ(既定の関連付けアプリ/Notepad/カスタム実行ファイル)で編集し、保存するたびに対象ペインへ自動送信する。旧`.NET`版の`MdiParentForm.cs`内`EditorBridge`クラスの移植。`add-editor-integration` change(2026-07-27 archive)で追加。

## Requirements

### Requirement: エディタ連携の起動
ペインのシステムメニュー「エディタ連携」またはCtrl+Eショートカットが操作されたとき、システムは対象ペイン用の一時ファイルを作成し、設定されたエディタで開かなければならない(SHALL)。対象ペインに既にアクティブなブリッジ(一時ファイルが存在し監視中の状態)が存在する場合は、新規作成せず既存の一時ファイルに対してエディタを再起動しなければならない(SHALL)。

一時ファイルのパスは `%LOCALAPPDATA%\amm\editor\prompt-<プロファイル名>-<6文字のランダムID>.md` とし、ファイル名として不正な文字は `_` に置換しなければならない(SHALL)。プロファイルに紐付かないペインの場合はプロファイル名部分を `pane` とする。

一時ファイルの初期本文は、対象ペインの入力欄に文字列があればその内容、無ければ「保存するたびに対象ペインへ送信される」旨の説明コメントとしなければならない(SHALL)。

#### Scenario: 入力欄が空の状態でエディタ連携を起動する
- **WHEN** 入力欄が空の状態でペインの「エディタ連携」を操作する
- **THEN** 説明コメントのみを本文とする一時ファイルが作成され、設定されたエディタで開かれる

#### Scenario: 入力欄に文字列がある状態でエディタ連携を起動する
- **WHEN** 入力欄に文字列が入力された状態でペインの「エディタ連携」を操作する
- **THEN** その文字列をそのまま本文とする一時ファイルが作成され、設定されたエディタで開かれる

#### Scenario: 既にブリッジが存在するペインで再度エディタ連携を起動する
- **WHEN** 同一ペインに対して既にアクティブなブリッジが存在する状態で再度「エディタ連携」を操作する
- **THEN** 新しい一時ファイルは作成されず、既存の一時ファイルに対してエディタが再起動される

### Requirement: エディタ選択設定に基づくエディタ起動
システムはエディタ全体設定(エディタモード: 既定の関連付けアプリ/Notepad/カスタム実行ファイル)に従ってエディタを起動しなければならない(SHALL)。カスタム実行ファイルが設定されているがそのパスが存在しない場合、既定の関連付けアプリへフォールバックしなければならない(SHALL)。

#### Scenario: 既定の関連付けアプリでエディタ連携を起動する
- **WHEN** エディタモードが「既定の関連付けアプリ」に設定された状態でエディタ連携を起動する
- **THEN** OSの関連付けに従ったアプリケーションで一時ファイルが開かれる

#### Scenario: カスタムエディタのパスが不正な状態で起動する
- **WHEN** エディタモードが「カスタム」だが指定された実行ファイルパスが存在しない状態でエディタ連携を起動する
- **THEN** 既定の関連付けアプリへフォールバックして一時ファイルが開かれる

### Requirement: 保存監視による自動送信
システムはアクティブなブリッジの一時ファイルの変更を監視し、変更が検知され500ms以上変更が無い状態が続いたとき、ファイル内容を読み取って対象ペインへ送信しなければならない(SHALL)。送信前に、既存のコメント行フィルタ処理を適用しなければならない(SHALL)。フィルタ適用後の内容が空文字列の場合、または直前に送信した内容と同一の場合は送信してはならない(SHALL NOT)。

#### Scenario: 一時ファイルを保存すると対象ペインへ送信される
- **WHEN** エディタで一時ファイルを編集して保存し、500ms以上追加の変更が無い
- **THEN** コメント行フィルタ適用後の内容が対象ペインへ送信される

#### Scenario: 同一内容を連続して保存しても再送信されない
- **WHEN** 直前に送信済みの内容と同一の内容で一時ファイルを再度保存する
- **THEN** 対象ペインへの再送信は行われない

#### Scenario: フィルタ適用後に空文字列になる内容を保存する
- **WHEN** コメント行のみで構成された内容を一時ファイルに保存する
- **THEN** フィルタ適用後の内容が空文字列となり、対象ペインへの送信は行われない

### Requirement: 送信後アクション
システムは送信後アクション設定(フォーカス/最大化/何もしない)に従って、送信直後の対象ペインの状態を変更しなければならない(SHALL)。既定値は「フォーカス」とする(SHALL)。

#### Scenario: 送信後アクションが「フォーカス」の場合
- **WHEN** 送信後アクションが「フォーカス」に設定された状態で一時ファイルの保存による送信が発生する
- **THEN** 対象ペインがフォーカスされる

#### Scenario: 送信後アクションが「最大化」の場合
- **WHEN** 送信後アクションが「最大化」に設定された状態で一時ファイルの保存による送信が発生する
- **THEN** 対象ペインが最大化され、かつフォーカスされる

#### Scenario: 送信後アクションが「何もしない」の場合
- **WHEN** 送信後アクションが「何もしない」に設定された状態で一時ファイルの保存による送信が発生する
- **THEN** 対象ペインの表示状態は変更されない

### Requirement: エディタ連携ファイルパスのコピー
ペインのシステムメニュー「エディタ連携ファイルパスをコピー」が操作されたとき、システムは対象ペインのアクティブなブリッジの一時ファイルパスをクリップボードへコピーしなければならない(SHALL)。対象ペインにアクティブなブリッジが存在しない場合、新規にブリッジを作成した上でそのパスをコピーしなければならない(SHALL)。この操作はエディタを起動してはならない(SHALL NOT)。

#### Scenario: 既存ブリッジがある状態でパスをコピーする
- **WHEN** 対象ペインに既にアクティブなブリッジが存在する状態で「エディタ連携ファイルパスをコピー」を操作する
- **THEN** 既存の一時ファイルパスがクリップボードへコピーされ、エディタは起動されない

#### Scenario: ブリッジが無い状態でパスをコピーする
- **WHEN** 対象ペインにアクティブなブリッジが存在しない状態で「エディタ連携ファイルパスをコピー」を操作する
- **THEN** 新規に一時ファイルとブリッジが作成され、そのパスがクリップボードへコピーされる(エディタは起動されない)

### Requirement: ブリッジのクリーンアップ
対象ペインが閉じられたとき、システムはそのペインに紐づくアクティブなブリッジを破棄し、対応する一時ファイルを削除しなければならない(SHALL)。

#### Scenario: エディタ連携中のペインを閉じる
- **WHEN** アクティブなブリッジを持つペインを閉じる
- **THEN** 監視が停止され、対応する一時ファイルが削除される

### Requirement: エディタ全体設定の永続化
システムはエディタモード・カスタムエディタパス・送信後アクションの3設定をアプリケーション全体設定として永続化し、アプリケーション再起動後も復元しなければならない(SHALL)。この設定はプロファイル単位ではなくアプリケーション全体で共有されなければならない(SHALL)。設定は `%LOCALAPPDATA%\amm\editor-settings.json` に保存する(非admin環境の`C:\Program Files\`配下インストールでも書き込めるようにするため、exe隣接ではなくこの配置とする)。

#### Scenario: 設定変更後にアプリを再起動する
- **WHEN** エディタモードを「カスタム」に変更し、実行ファイルパスを指定してアプリを再起動する
- **THEN** 再起動後もエディタモードとカスタムパスの設定が保持されている

#### Scenario: 異なるプロファイルのペイン間で設定を共有する
- **WHEN** 送信後アクションを「最大化」に変更した状態で、異なるプロファイルから起動した別のペインでエディタ連携を使用する
- **THEN** そのペインでも同じ「最大化」の送信後アクションが適用される
